集成测试的 Helm 执行

spark-milvus-integration Chart 只创建一个 Kubernetes Job；Job 执行测试镜像自带的入口，访问已有的 Milvus 和对象存储。

当前状态：Chart 的部署合同已经确定。公开发布镜像只有 Connector assembly，没有测试运行器，不能直接用于该 Chart；具体部署可以使用在其他代码库维护的测试镜像和测试集合。

3. 一次 release 对应一次测试

  1. CI 生成唯一的 Helm release 和 runId。
  2. 命名空间及其 Secret 由集群既有流程预先创建；运行脚本拒绝创建命名空间或覆盖同名 release。
  3. 运行脚本先执行 helm lint --strict，再安装 Job；脚本监控 Complete、Failed，以及 ErrImagePull、ErrImageNeverPull、ImagePullBackOff、InvalidImageName、CreateContainerConfigError、RunContainerError 和 Unschedulable，并在无法启动时立即失败。脚本不主动读取凭据 Secret 的 data。Helm 默认以 Secret 保存 release metadata，CI 身份仍需具备 Helm 自身要求的 Secret 权限。
  4. Job 失败不由 Kubernetes 重试：backoffLimit 固定为 0，避免重复写入。
  5. 成功或失败都先收集 Helm 状态、Job 日志、资源描述和相关 Events。
  6. 收集完成后卸载 release；成功测试若卸载失败，CI 仍判失败。TTL 只负责 CI 被强制中断后的 Job 兜底回收。

安装不使用 --atomic。该参数会在失败时先删除 Job，使 CI 失去诊断现场。

4. 测试镜像提供固定入口

Chart 默认调用 /opt/spark-milvus/bin/run-integration-tests；镜像拥有该入口的实现。测试镜像必须：

  • 包含 Spark 4.0、待验证的 Connector assembly、对应的原生 bundle 和测试入口所需的依赖；
  • 以明确的数字 UID 非 root 用户运行，保证工作目录与临时目录可写；
  • 读取 Chart 注入的环境变量，执行有界测试，并原样返回测试退出码。

测试入口不必在公开仓库维护；部署方可以在自己的镜像中实现业务测试。公开发布镜像的 final stage 只有 Connector assembly，没有该入口，不能直接用作测试镜像。

5. runId 必须进入所有可变资源

Helm 已把 runId 传入 CI_RUN_ID，并用于测试写入前缀。测试代码还必须用它派生 collection、snapshot 和 writer 路径，并在结束时只删除本次运行拥有的资源。仅给每次运行换一个时间戳不能证明重试安全。

ConnectorWriteReadUatTest 和 DataFrameScenariosUatTest 的 S10/S13 在配置的写入前缀下，按 case、CI_RUN_ID（本地未配置时使用 local）和随机 UUID 分配独立目录；S10 的两种读取模式也分别分配目录。提交记录只从该目录发现，成功和异常退出均清理自己的文件，并关闭存储句柄；显式保留写入产物的选项仍有效。清理失败必须使测试失败，不能覆盖原始断言错误。进程被强制终止时无法执行 finally，后续重试使用新目录避免读到残留；旧目录的回收是独立任务，不允许测试通过扫描公共前缀删除其他运行的数据。

CorrectnessJob 创建 collection 时同样携带运行标识和 UUID，只按确切名称清理和检查删除结果，不批量删除固定名称前缀下的 collection。用例选择必须非空，且显式请求的每个 case 都存在；未知 group 或 case 直接失败。最终结果必须与选中的 case 一一对应且全部为 PASS，SKIP 仍记录原因但退出码非零。这些修改不表示公开测试已经接入私有 smoke 镜像，也不替代真实 Milvus/S3 的重复与并发验收。
