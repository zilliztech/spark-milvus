只读 Catalog

对应能力索引中的 R1、R2。固定快照与四种来源见 snapshot.html，读取执行见 read.html。

Catalog 只把 Spark 的三段表名和时间旅行参数翻译成一个固定 Snapshot，随后交给现有 MilvusTable；它不另建读取链路。 普通加载取最新快照，版本加载按快照名精确匹配，时间加载把 Spark 的 Unix 微秒转换成 Milvus HybridTS 上界后选择不晚于该边界的最新快照。

一、名称与配置

只接受 catalog.database.collection。 Spark 已经从标识符中移除了 catalog 名，传给 MilvusCatalog 的 Identifier 必须恰有一段 namespace；它是 Milvus database，table name 是 collection。二段名没有默认 database，四段名也不截断。

spark.sql.catalog.milvus = com.zilliz.spark.connector.catalog.MilvusCatalog
spark.sql.catalog.milvus.milvus.uri = https://example-milvus:19530
spark.sql.catalog.milvus.milvus.token = user:password
spark.sql.catalog.milvus.fs.address = s3.us-west-2.amazonaws.com
spark.sql.catalog.milvus.fs.bucket_name = your-milvus-bucket
spark.sql.catalog.milvus.fs.root_path = files
spark.sql.catalog.milvus.fs.cloud_provider = aws
spark.sql.catalog.milvus.fs.region = us-west-2
spark.sql.catalog.milvus.fs.use_ssl = true
spark.sql.catalog.milvus.fs.use_iam = true
SELECT id, embedding FROM milvus.default.products
输入处理原因
spark.sql.catalog.<name>.*Spark 去掉前缀后交给 initialize；Catalog 保存不可变副本一次注册可承载连接、对象存储和读取选项
database、collection总是由本次 Identifier 覆盖同名配置一个 Catalog 可以安全加载多张表，初始化配置不能把名字串到另一张表
snapshot、backup 离线模式拒绝离线文件没有可验证的三段目录关系，继续由 format("milvus") 承载

已知表名的加载只调用现有 getCollectionInfo(database, collection) 取得 collection id； 它不依赖列数据库或列 collection 的 RPC。SHOW NAMESPACES、SHOW TABLES 属于 C1， 本阶段不实现 SupportsNamespaces。

二、一次解析，沿用一条读链

三个入口只在快照选择方式上不同。 选中的 Snapshot 在 loadTable 内解析一次并放进 MilvusTable；schema、ScanBuilder、分区规划和 reader 使用同一个对象，不在 executor 或 scan 创建时重新查询最新快照。

Spark 调用快照选择
loadTable(identifier)SnapshotCatalog.latest
loadTable(identifier, version)非空的 version 作为快照名，调用 byName
loadTable(identifier, timestamp)Unix 微秒先转 HybridTS 上界，再调用 asOf

三、时间参数在 Catalog 边界换单位

Spark 的时间是 Unix epoch 微秒，snapshot_info.create_ts 是 Milvus HybridTS。 后者的高位是 Unix epoch 毫秒，低 18 位是同一毫秒内的逻辑时钟；它表示各 channel seek position 的最小快照边界，不是 API 调用完成时间。Snapshot.createdAt 保留 原始 HybridTS，core 的 SnapshotCatalog.asOf 合同不改变。SQL 时间字面量先按 spark.sql.session.timeZone 解析；loadTable(identifier, timestamp) 收到的是 UTC epoch 微秒。

Catalog 先令 millis = floorDiv(epochMicros, 1000)，再生成该毫秒的最大 HybridTS： (millis << 18) | ((1 << 18) - 1)。低 18 位必须全为 1，否则同一毫秒内 logical 大于 0 的快照会被漏掉。负时间饱和到 Long.MinValue，超过 HybridTS 可表示范围的 时间饱和到 Long.MaxValue，两端都不发生移位溢出。

时间旅行只选择已有快照元数据，不提供保留策略。 Connector 不保留旧段文件； compaction 或 GC 回收快照引用的段后，按名字或时间选中该快照仍可能在读取数据文件时失败。

四、失败与只读边界

无效请求在 driver 规划期失败，只把能够确认的“不存在”翻成 Spark 标准语义。 名称层级错误、空版本、非 client 模式给出 IllegalArgumentException；Milvus 明确返回 collection / database 不存在时，Catalog 抛 NoSuchTableException，使 tableExists 和 SQL 缺表行为符合 Spark 约定。collection 已存在但指定名字或时间点 没有快照候选时，保留含选择条件和 metadata prefix 的 SnapshotNotFoundException；整个 prefix 为空也保留明确错误，因为它可能是尚无快照，也可能是 bucket 或 fs.root_path 配错。 缺失或冲突的 create_ts、网络、认证、对象存储和解析异常同样保留原错误链，不能被改成 空表或 false。

只读是接口边界。 listTables、create、alter、drop、rename 都明确抛出 UnsupportedOperationException。本阶段不新增列表 RPC、缓存、DDL、Procedure、 Scan、对象存储或原生实现。这里的“只读”只指 Catalog 元数据操作；已加载的 MilvusTable 仍沿用现有 append 写链。

五、四条 Spark 线

三个 loadTable 签名在 Spark 3.5、4.0、4.1、4.2 一致，主体放在 spark-base。 每条线只保留公开的无参 MilvusCatalog 和本线首选 createTable 签名；它们都把 create 明确判为不支持。测试先验证共享行为，再让四条线各自 编译，Spark 3.5 同时验证 Scala 2.12 与 2.13。
