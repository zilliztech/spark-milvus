只读 Catalog

对应能力索引中的 R1、R2、C1。固定快照与四种来源见 snapshot.html，读取执行见 read.html。

Catalog 有两条互不混合的只读路径：目录发现只调用 Milvus 的 ListDatabases 和 ShowCollections；表加载把 Spark 三段表名和时间旅行参数 翻译成一个固定 Snapshot，随后交给现有 MilvusTable。目录发现不打开 对象存储、不读取快照、不规划 Scan；表加载也不靠先列全库或全 collection 来确认一个已知名字。

一、名称与配置

只接受 catalog.database.collection。 Spark 已经从标识符中移除了 catalog 名，传给 MilvusCatalog 的 Identifier 必须恰有一段 namespace；它是 Milvus database，table name 是 collection。二段名没有默认 database，四段名也不截断。

spark.sql.catalog.milvus = com.zilliz.spark.connector.catalog.MilvusCatalog
spark.sql.catalog.milvus.milvus.uri = https://example-milvus:19530
spark.sql.catalog.milvus.milvus.token = user:password
spark.sql.catalog.milvus.fs.address = s3.us-west-2.amazonaws.com
spark.sql.catalog.milvus.fs.bucket_name = your-milvus-bucket
spark.sql.catalog.milvus.fs.root_path = files
spark.sql.catalog.milvus.fs.cloud_provider = aws
spark.sql.catalog.milvus.fs.region = us-west-2
spark.sql.catalog.milvus.fs.use_ssl = true
spark.sql.catalog.milvus.fs.use_iam = true
SHOW NAMESPACES IN milvus;
SHOW TABLES IN milvus.default;
SELECT id, embedding FROM milvus.default.products;
输入处理原因
spark.sql.catalog.<name>.*Spark 去掉前缀后交给 initialize；Catalog 保存不可变副本一次注册可承载连接、对象存储和读取选项
database、collection表加载与目录发现都以本次标识符为准；初始化配置里的同名 option 不限制目录，也不覆盖标识符一个 Catalog 可以安全访问多个 database 和 collection
snapshot、backup 离线模式拒绝离线文件没有可验证的三段目录关系，继续由 format("milvus") 承载

已知表名的加载只调用现有 getCollectionInfo(database, collection) 取得 collection id； 它不先调用目录 RPC。目录发现只需 milvus.uri 与认证配置；对象存储配置只在加载表和读取 数据时使用。

二、单层目录

Catalog 根目录的直接子项是 Milvus database，database 的直接表是 collection；没有第二层 namespace。目录名与 collection 名按 Milvus 返回值原样交给 Spark，不转小写、不裁空白、不改名、 不去重。返回顺序不是接口合同，调用方和测试不能依赖服务端顺序。

空 database 的 listTables 返回空数组，不等于 database 不存在。ShowCollections 列出 Milvus 元数据里的全部 collection，即使某个 collection 还没有可读快照；目录发现不以快照目录 是否存在来过滤结果。SHOW TABLES ... LIKE 的匹配由 Spark 在结果上完成，Connector 不另发 带模式的 RPC。

listNamespaces 收到两段或更多段时抛 NoSuchNamespaceException； listTables 必须恰有一段 database，根目录和嵌套名字都抛同一 Spark 标准异常。因此 SHOW TABLES IN milvus 不会隐式使用 default，也不会把多个 database 的 collection 摊成一张表。namespaceExists 对根目录或嵌套名字返回 false。

Catalog 不缓存目录。每次发现都创建一个短生命周期的 MilvusClient，成功和失败都关闭； 结果反映本次 RPC 对当前凭证可见的 database 与 collection。

三、一次解析，沿用一条读链

三个入口只在快照选择方式上不同。 选中的 Snapshot 在 loadTable 内解析一次并放进 MilvusTable；schema、ScanBuilder、分区规划和 reader 使用同一个对象，不在 executor 或 scan 创建时重新查询最新快照。

loadTable(identifier, version)非空的 version 作为快照名，调用 byName
loadTable(identifier, timestamp)Unix 微秒先转 HybridTS 上界，再调用 asOf

四、时间参数在 Catalog 边界换单位

Spark 的时间是 Unix epoch 微秒，snapshot_info.create_ts 是 Milvus HybridTS。 后者的高位是 Unix epoch 毫秒，低 18 位是同一毫秒内的逻辑时钟；它表示各 channel seek position 的最小快照边界，不是 API 调用完成时间。Snapshot.createdAt 保留 原始 HybridTS，core 的 SnapshotCatalog.asOf 合同不改变。SQL 时间字面量先按 spark.sql.session.timeZone 解析；loadTable(identifier, timestamp) 收到的是 UTC epoch 微秒。

Catalog 先令 millis = floorDiv(epochMicros, 1000)，再生成该毫秒的最大 HybridTS： (millis << 18) | ((1 << 18) - 1)。低 18 位必须全为 1，否则同一毫秒内 logical 大于 0 的快照会被漏掉。负时间饱和到 Long.MinValue，超过 HybridTS 可表示范围的 时间饱和到 Long.MaxValue，两端都不发生移位溢出。

时间旅行只选择已有快照元数据，不提供保留策略。 Connector 不保留旧段文件； compaction 或 GC 回收快照引用的段后，按名字或时间选中该快照仍可能在读取数据文件时失败。

五、失败与只读边界

无效请求在 driver 规划期失败，只把能够确认的“不存在”翻成 Spark 标准语义。 表名层级错误、空版本、非 client 模式给出 IllegalArgumentException；表加载中 Milvus 明确返回 collection / database 不存在时，Catalog 抛 NoSuchTableException，使 tableExists 和 SQL 缺表行为符合 Spark 约定。collection 已存在但指定名字或时间点 没有快照候选时，保留含选择条件和 metadata prefix 的 SnapshotNotFoundException；整个 prefix 为空也保留明确错误，因为它可能是尚无快照，也可能是 bucket 或 fs.root_path 配错。 缺失或冲突的 create_ts、网络、认证、对象存储和解析异常同样保留原错误链，不能被改成 空表或 false。

目录发现只把两类已确认的结果翻成 Spark 语义：成功 RPC 的空名字列表是空结果；Milvus 明确报告 database 不存在时是 NoSuchNamespaceException，而 namespaceExists 才返回 false。认证、授权、网络、超时、限流、RPC 不可用、非成功状态与响应解析失败保留原异常链， 不能伪装成空目录、空 collection 列表或 namespace 不存在。异常带操作名与请求的 database，但不带 token 或对象存储密钥。

只读边界覆盖元数据修改；目录发现属于读取。 createNamespace、alterNamespace、dropNamespace 以及 table 的 create、alter、drop、rename 都明确抛出 UnsupportedOperationException。Catalog 不提供 namespace owner、comment、location、database id 或创建时间；loadNamespaceMetadata 只确认 database 存在并返回空表。目录发现也不新增缓存、Procedure、Scan、对象存储或原生实现。已加载的 MilvusTable 仍沿用现有 append 写链。

六、四条 Spark 线

TableCatalog 与 SupportsNamespaces 的这组接口在 Spark 3.5、4.0、 4.1、4.2 共用一份主体，放在 spark-base。 每条线只保留公开的无参 MilvusCatalog 和本线首选 createTable 签名；它们都把 create 明确判为不支持。 行为测试覆盖目录矩阵、异常保真、Spark SQL 路由和表加载；同一份共享实现再由四条线分别编译， Spark 3.5 同时验证 Scala 2.12 与 2.13。
