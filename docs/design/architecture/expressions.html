Spark 与 Milvus 谓词求值

能力 R6、R7 · spark.expr 翻译 · core.expr 求值

连接器只接受能够完整保持 Spark SQL 语义的 DataSource V2 Predicate；普通表也可通过 milvus.filter 使用已交付的 Milvus 标量表达式子集。 两种表达式在 executor 的同一 Arrow 列批上独立求值，最终共同决定存活行。

本设计覆盖能力索引中的 R6，以及 R7 已交付的标量子集。R7 的手写 PlanParser 与 MilvusSearch.filter / vector.search.filter 标量子集 保留既有 Expr / Evaluator 合同，普通表的 milvus.filter 复用它。 R6 使用按字段 id 和类型绑定的 PredicateExpr / PredicateEvaluator；两套中间表示不能互转， 因为 Spark 与 Milvus 的字面量和浮点比较合同不同。JSON、Array、json_contains 仍由开放决策 23 阻塞。 读任务、删除和列式出口见 读路径，模块边界见模块设计。

一、公开语义

一次普通 where 可以同时包含已支持与未支持的顶层谓词，Spark 仍得到完整结果。 MilvusScanBuilder 实现 SupportsPushDownV2Filters。对 Spark 传入数组中的每个 顶层 Predicate，翻译成功就由连接器执行，翻译失败就把原对象作为 residual 返回给 Spark。 一个谓词树内部不拆分：任意子节点不支持，整棵树都不下推。

字段类型连接器接受留给 Spark
Bool =、<>、<=>、IN、 IS NULL、IS NOT NULL 有序比较、字符串操作
Int8 / Int16 / Int32 / Int64、Float / Double =、<>、<、<=、 >、>=、<=>、IN、 IS NULL、IS NOT NULL 算术表达式、cast、函数调用
String / VarChar / Text 数字类型所列比较与空值判断，加 STARTS_WITH、 ENDS_WITH CONTAINS、正则、非二进制 collation
JSON、Array、Geometry、向量 无 全部谓词；JSON 与 Array 的 Milvus 语义留给 R7
_timestamp schema metadata 将它绑定到真实字段 id 1 时，按 Int64 处理 缺少真实字段 metadata 时全部保留
_segment_id、_row_offset 无 它们是 reader 合成列，不进入核心求值器

AND、OR、NOT 只有在全部后代都能翻译时才接受。 Spark 可能传入的其他 V2 表达式节点、嵌套 NamedReference 和未知操作符均保留。 2.0 不实现 DataSource V1 Filter，ScanBuilder 也不同时实现 V1 与 V2 接口。

milvus.filter 接受比较、IN / NOT IN、IS NULL / IS NOT NULL 与 AND / OR / NOT 的标量子集，字段限 Bool、 整数、Float、Double、String、VarChar 与 Text。option 缺失表示不启用；显式空值、语法错误、未知字段、 不支持的字段类型和不匹配的字面量都在 driver 规划时失败。普通表上的 Spark predicate 与 milvus.filter 按 AND 合并；任一入口都不能静默忽略另一个入口。

二、driver 只翻译和绑定

driver 把 Spark 对象变成按 Milvus 字段 id 引用的可序列化 PredicateExpr，executor 不接收 Spark 表达式对象。翻译器只接受单段 NamedReference，从固定快照产生的 StructField metadata 读取 milvus.field_id 与 Milvus 逻辑类型，再把 Spark 字面量规范化成对应的核心类型。翻译时找不到字段，或字段 metadata 缺失、损坏、与 Spark 类型冲突， 该谓词原样留给 Spark。

字面量必须能够无损归一到字段类型。整数越界、字符串与数字混用、集合中出现不兼容类型等情况 使该 Spark 谓词成为 residual；翻译器不靠 toString 比较，也不做会改变结果的隐式转换。 同一字段在 V2 段按字段名存储、在 V3 段按字段 id 存储，这个差异由 executor 的 columnNameFor(fieldId) 处理，PredicateExpr 不保存物理列名或 ordinal。

三、输出列与求值列分开

任一谓词引用的列即使没有被 select 输出，也必须从段中读取；读取它不改变 Spark 看到的 schema。ScanBuilder 分别维护输出 schema 与内部所需字段 id。内部集合是投影字段、 Spark predicate 字段、milvus.filter 字段、删除与其他 reader 内部字段的并集；输出仍严格等于 Spark 的 required schema。完整推导的 schema 没有发生 Spark 列裁剪，且已包含全部 filter 字段时，继续用 空字段列表表示读取全部字段，不能把它误收窄为只读取 filter 字段。外部 schema 隐藏了 filter 字段时则显式 读取输出字段与隐藏 filter 字段的并集。

例如 df.select("title").where($"price" > 10) 会读取 title 与 price，求值后只交付 title。Spark 可以先调用 pushPredicates，也可以先调用 pruneColumns；两种顺序产生相同的内部字段集合。空投影与仅元数据投影所需的 fallback 物理列遵守同一规则，任何内部列都不能泄漏到输出。

四、求值采用 Spark SQL 三值逻辑

每个子表达式的结果是 TRUE、FALSE 或 UNKNOWN，最终只有 TRUE 行通过。 核心求值器在列批内保留 UNKNOWN，直到整棵树求值完成；最终 Bitmap 以 bit=1 表示该行 应排除。FALSE 与 UNKNOWN 都置 1。reader 逐行把该结果与既有删除判定做逻辑 OR， 不需要构造第二张删除位图。

  • 普通比较、STARTS_WITH 和 ENDS_WITH 遇到 NULL 返回 UNKNOWN。
  • <=> 是 null-safe equality：两个 NULL 为 TRUE，只有一侧 NULL 为 FALSE，结果没有 UNKNOWN。
  • IN 只要有一个相等项就为 TRUE；没有命中且候选含 NULL 时为 UNKNOWN；其余为 FALSE。空候选集为 FALSE。
  • IS NULL 与 IS NOT NULL 始终返回 TRUE 或 FALSE。
  • Float 与 Double 遵守 Spark 的数值比较：NaN 与自身相等并大于所有非 NaN 数值，-0.0 与 0.0 相等。
  • String、VarChar 与 Text 使用默认二进制 collation 的 UTF-8 等值、顺序与前后缀语义。

以上表格与列表是 R6 的 Spark SQL 合同。R7 的 Expr 保留 Milvus 标量合同：浮点字面量按目标 字段精度转换，字符串按 UTF-8 字节比较，最终同样只有 TRUE 行通过。reader 分别取得两个排除位图后做 OR； 这等价于用户条件做 AND，但不把其中一种语义改写成另一种。

五、executor 先确定存活行，再交付或计数

PredicateEvaluator 与 Evaluator 都对行式和列式出口求整批位图，过滤发生在 Limit 之前。 每个 Arrow 批先完成两种表达式求值，reader 再逐行合并两个排除位图与删除判定。行式 reader 只迭代存活位置； 列式 reader 用存活位置数组构造 SelectedRowsColumn，继续保持列式默认路径，不复制整列 buffer。

  1. SegmentReader 读取包含输出列和内部求值列的 Arrow 批。
  2. PredicateEvaluator 按 field id、Evaluator 按字段名经 ColumnBinding 找列，各自生成排除位图。
  3. reader 逐行计算删除、Spark predicate 与 Milvus filter 三个排除条件的逻辑 OR。
  4. reader 交付存活行；分区 Limit 只对已交付的存活行计数。
  5. 批与 reader 按原有所有权规则关闭，谓词求值不延长 Arrow buffer 生命周期。

全过滤批返回零行并继续读取下一批。删除关闭时只省略删除位图，表达式仍执行。已知物理行数的 EOF 校验统计 native reader 交付的物理行数，不用过滤后的行数替代。

六、失败和边界保持可见

不支持的 Spark 语法留给 Spark，已经接受的谓词在执行失败时让 task 失败。 这两类情况不能互相转换。

情况结果
操作符、字段类型、字面量形状或嵌套引用不在支持矩阵整个顶层 Predicate 作为 residual 返回
翻译器找不到字段 id metadata，或 metadata 与 Spark 类型冲突整个顶层 Predicate 作为 residual 返回
Spark 要求物理读取的 required schema 字段缺少 field id既有列裁剪校验使规划失败
executor 找不到已绑定字段、Arrow vector 类型不符、批长度不一致task 失败；不返回空结果或全 false
带 vector.search.* 的读不接受 milvus.filter，明确报错并提示使用 vector.search.filter；Spark predicate 全部作为 residual 留给 Spark，在 TopK 后求值
milvus.filter 显式空值、语法错误、未知字段、类型或字面量不匹配driver 规划失败，错误包含 option 键和具体原因
executor 找不到 milvus.filter 已验证的物理列，或列长度不足task 失败；不返回空结果或全 false
R7 与 R6 保持独立入口。同一个 R7 标量实现服务普通表 milvus.filter 与向量查询的 vector.search.filter，但两个 option 不能在一次读取中混用。 JSON path、JSON null 与缺失值、Array 和 json_contains 必须先解决开放决策 23；核心模块不会引入 antlr。

七、实现必须保持的合同

  • 四条 Spark 线共用一份 V2 翻译实现；Spark 4.2 的可选接口扩展不产生第二条路径。
  • 同一输入在行式与列式出口得到相同行集合，在 V2 与 V3 段得到相同结果。
  • 投影掉谓词列、删除与谓词同时生效、NULL 组合、空批和全过滤批都不改变输出 schema。
  • 所有 accepted predicates 都由连接器完整执行；所有 residual predicates 都由 Spark 完整执行。
  • milvus.filter 只在普通扫描执行，并与已接受的 Spark predicate、删除位图及 Limit 正确组合。
  • core.expr 源码不依赖 Spark，表达式描述不持有 Arrow vector、native handle 或打开的资源。
