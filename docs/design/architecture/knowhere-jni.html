Knowhere JNI 实现方案

为 spark-milvus 提供 Knowhere 的索引构建、加载、搜索、序列化与暴力搜索 C ABI / Java JNI 绑定。Cardinal Aquila 的 11 项扩展首期暂缓。

2. 实现路径与代码归属

JNI（Java Native Interface）负责 Java 与 native 的参数和生命周期交接；C ABI（Application Binary Interface）规定编译后函数和数据的交接。Knowhere 核对基线已有 Python SWIG 绑定，尚无 Java/JNI 和公共 C API。当前实现新增 knowhere_* C 接口与 io.knowhere Java 包，基于 Java 11，无 Spark、Scala、Arrow Java 或 Hadoop 依赖。当前 Connector 设计中的 mv_* 尚无已发布实现。

首期 C 合同采用 knowhere_vectors（地址、字节数、行数、维度、dtype）、knowhere_bitset 与 knowhere_search_result 传递批次；资源使用不重用的 64 位句柄。错误返回状态码，线程本地消息由 JNI 立即转换；创建时校验索引格式版本。Java 使用 direct ByteBuffer 的 position/limit 作为有效区域。dense 五种 dtype 按上游注册组合分派，FLAT、HNSW、IVF_FLAT 与 BF 用真实调用验证；DiskANN 以启用构建及文件往返测试确定支持。

Java API 版本、C ABI 版本与索引格式版本分别记录。创建或加载索引时传入其格式版本；Maven version 不能替代这一参数。上游 Version 的 current/maximum 不能证明任意 Milvus 索引均可读取，兼容范围以实际测试为准。

3.1 线程模型：每条查询一个任务，任务内单线程

Knowhere 的搜索并行度等于一次调用的查询数。brute_force.cc 的 SearchWithBuf 与 faiss_hnsw.cc 的搜索都对每条查询向全局搜索池 push 一个任务，任务内 ScopedSearchOmpSetter(1) 把 OpenMP 与 OpenBLAS 线程数设为 1。nq = 1 的调用只占一个线程。批量距离入口是例外：不进搜索池，在调用线程上单线程执行，并行由调用方（Spark 任务）承担。

全局搜索池在首次使用时按 std::thread::hardware_concurrency() 懒创建，进程内所有调用共享；核心的 KnowhereConfig::SetSearchThreadPoolSize 与 SetBuildThreadPoolSize 可在运行中调整大小。首期绑定没有开放配置入口；PR #1829 自 1fff20db（2026-09-17）起增加 knowhere_search_thread_pool_resize、knowhere_search_thread_pool_size 与 build 池的对应函数，Java 为 Knowhere.resizeSearchThreadPool、searchThreadPoolSize、resizeBuildThreadPool、buildThreadPoolSize；大小限定 1 到 INT32_MAX，读取在池创建前返回 0。Linux x86-64 上 C 测试 3/3、JNI 测试 11/11 通过，macOS arm64 同样通过。SIMD、BLAS 阈值与日志仍无入口。

对 Connector 的含义：现状每个 Spark 任务一条查询，并行度来自任务数，池大小无关紧要；改为多查询后每次调用把 nq 个任务推进池，c 个并发任务的 CPU 需求为 c × 池大小。pin 升级后，Connector 在 executor 首次搜索前调用 Knowhere.resizeSearchThreadPool(spark.executor.cores)；Spark 侧的处理见向量搜索与建索引 1.1。

聚类、去重、异常评分与文件转换参考

聚类：Java 交给 native 文件路径和当前中心，native 抽样、预处理和分配，再把每簇 sums/counts/costs 返回。trainAssign 实现只执行一次分配与统计；多轮中心更新、跨分区聚合由调用方组织，不应把“存在训练 JNI”解释为 native 已完成完整的分布式 KMeans 调度。

去重：dedupPartition 实现按数据量选择 BF 或 Cardinal Index，取 top-k 候选后按阈值连边，再用 union-find 合并。即使头文件仍写 range_filter，当前代码也不能理解为枚举阈值内全部邻居。L2 输入阈值会平方；cosine 是相似度阈值，BF 路径依赖已归一化向量。代表是同一分量中 .dist 值最小的行；component ID 来自并查集根的原始 ID，未必等于代表 ID。这些语义必须用测试锁定。

去重参数完整覆盖参考实现的 adsampling_epsilon0、index_threshold、bf_batch_size、index_batch_size、index_query_batch、ef、graph_width、topk、bf_quant_type、build_quant_type、search_quant_type、refine_quant_type、kmeansfast_precision、kmeansfast_epsilon，见配置解析。四个 batch/threshold 大小参数中的 index_threshold 与三个 batch 参数按 MB 计算，不能当行数传入。

Isolation Forest：训练与评分使用平铺数组保存节点特征、分割值、左右子节点和树根。训练调用 Cardinal build pool，评分调用 search pool。评分为平均路径长度经 2^(-平均路径长度 / avgPath) 归一化；叶节点的路径修正值保存在 splitValue 中。两个 FromAddress 入口借用 native 向量内存，不能在方法返回前释放或修改该区域。

文件转换：parquetToFbin由 Arrow C++ 读取本地 Parquet；fbin 格式为 little-endian 的两个 int32（行数、维度）及 float32 行数据，ids 为行数、1 及 int64 ID。参考实现写出原始向量，没有归一化步骤；cosine 去重的归一化前提由调用方满足。该本地转换能力恢复开发时再加入绑定，Milvus snapshot、binlog、对象存储与索引登记仍属于 Connector 的现有职责。

扩展恢复时的数组、地址与文件契约

参考 JNI 对字符串使用 RAII 释放 UTF 字符；数组输入以 JNI_ABORT 结束访问，输出以 mode=0 写回。新接口验证所有数组容量、维度、乘法溢出及路径参数；地址入口增加有效字节数，保持调用方持有内存直到同步调用结束。地址不是可由 JNI 自动验证有效性的对象，调用方必须保证其来自仍存活的分配。

Isolation Forest 输出节点数组容量至少为 nTrees × (2 × nSamples + 1)，树根数组至少为 nTrees；遍历前校验根、子节点及 feature 下标。参考头文件将返回值描述为节点数，但实现返回预留跨度，新 API 必须把两者区分清楚，不能只根据实际可达节点数分配后交给该实现。

参考数组入口在训练/评分期间持有 GetPrimitiveArrayCritical，而底层还会调度线程池并等待。新绑定保留数组功能，但使用受控复制或常规数组访问来跨越长计算，避免长时间占用 critical region；地址入口维持借用。所有 native 异常在边界转换，分配失败保留 JVM 异常，清理用 RAII，不能只释放资源却让 C++ 异常越过 JNI。

合法输入的功能与格式按参考版本对齐；非法 JSON、短数组、错误维度、空地址等由新接口明确报错。参考 dedup 对部分非法配置回落默认值、部分 C 头文件只写 -1 错误，而实现已有细分错误码，这些不是新接口需要复制的行为。差异测试应分别记录成功路径等价与错误检查增强。
