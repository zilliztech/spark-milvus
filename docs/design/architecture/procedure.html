CALL 过程

能力 A1 到 A5 的 SQL 入口，并记录 A7 尚未实现的安全边界。本页同时规定 CALL milvus.system.<name>(...) 怎么从文本变成一次调用，以及每个已实现过程的参数、结果表、 等待和失败语义。SQL 前端由 issue #17 落地；管理过程由 issue #141 补齐。

一个解析器扩展认出 CALL milvus.system.*,把它变成一个带过程和参数的逻辑节点; 一条 planner 策略把节点变成在 driver 上跑过程体的物理节点;结果是一张表。四条线共用一份代码, 只有 antlr 生成的解析器和 ParserInterface 的适配器按线各一份。 不用 Spark 4.0 才有的 ProcedureCatalog(2026-09-10 的决定),所以 3.5 线走的是同一条路, 能力表第 4 节原来写的「3.5 暴露为同名函数」不再需要。

一、语法

过程名固定三段 milvus.system.<name>;参数是位置参数加命名参数,值只能是常量。

CALL milvus.system.register('default.spark_uat_v3',
  staging          => 'c48b088d035ecd5/staging/job-1789478390101',
  `milvus.uri`     => 'http://localhost:19531',
  `milvus.token`   => 'db_admin:***',
  `fs.bucket_name` => 'zilliz-aws-iobwa4e5ki5u5cl',
  `fs.address`     => 's3.us-west-2.amazonaws.com',
  `fs.use_iam`     => 'true')
statement     : CALL procedureName '(' (argument (',' argument)*)? ')' EOF ;
procedureName : identifier '.' identifier '.' identifier ;
argument      : constant                     # positional
              | identifier '=>' constant     # named ;
constant      : STRING | INTEGER | DECIMAL | TRUE | FALSE | NULL ;
identifier    : IDENTIFIER | BACKQUOTED_IDENTIFIER ;
规则定的是什么
第一个位置参数是 collection，写法 'db.coll'；只写 'coll' 时先取 milvus.database.name，未提供才使用 default和读写选项 milvus.database.name、milvus.collection.name 同一份解析，一处实现
过程自己的参数用裸标识符命名:staging => '...'每个过程声明自己的参数表,名字、类型、是否必填
连接和存储选项用反引号包住的选项名命名:`milvus.uri` => '...'选项名和 .option() 的键完全一样,不另起一套拼写;反引号是 SQL 标识符里带点的标准写法
值只能是常量过程在 driver 上跑,不需要表达式;文法不依赖 Spark 的表达式文法,四条线一份
大小写:关键字和过程名不分,参数名不分,值原样和 Spark SQL 一致

连接与存储选项走命名参数而不是会话配置。只读 MilvusCatalog 已能为表加载 保存这些属性，但 CALL 是独立语句，不能从语法中确定要借用哪一个 Catalog 实例。每条语句因此 显式携带所需选项，让语句自足、复制出来就能跑。语句中的显式参数始终是唯一配置来源。

二、一次调用怎么走

  1. 解析器扩展。SparkSessionExtensions.injectParser 装一个 MilvusSqlParser(delegate)。 parsePlan 先把文本去注释、压空白、转小写,以 call milvus. 开头的才交给 antlr 生成的解析器, 其余全部原样交给 delegate。Spark 4 自己也有 CALL 语句(ProcedureCatalog), 不以 milvus. 开头的 CALL 不碰。其它 parseExpression 等方法全部转发。
  2. 逻辑节点。CallProcedure(procedure: Procedure, args: ProcedureArgs), LeafCommand,output 来自 procedure.outputSchema。 参数在建节点时按过程的参数表对好:位置参数按顺序填,命名参数按名字填,缺必填、多了不认识的、类型不对,都在这里抛。
  3. 策略。injectPlannerStrategy 装一条只认 CallProcedure 的策略,产出 CallProcedureExec。
  4. 物理节点。CallProcedureExec 是 LeafExecNode，在 driver 上调 procedure.run(args), 把 Seq[Row] 转成 InternalRow。spark.sql("CALL ...") 拿到的 DataFrame 就是这张表, .show()、.collect() 都行。

三、过程体的接口

trait Procedure {
  def name: String                          // register
  def parameters: Seq[Parameter]            // Parameter(name, dataType, required)
  def outputSchema: StructType
  def run(args: ProcedureArgs): Seq[Row]    // driver 上执行
}
object Procedures { def byName(name: String): Option[Procedure] }   // 注册表,静态

ProcedureArgs 装两部分:过程自己的参数(按参数表取值),和连接、存储选项(反引号命名参数收集成的 Map[String, String],交给现有的 MilvusOption 解析)。过程体不碰 SQL,不碰 Spark 计划。 普通管理过程共用 collection 解析、client 创建与关闭、可选等待；register 另需对象存储，继续复用 Register.run(options, stagingPrefix)。

3.1 共同行为

  • collection 只接受 db.collection 或 collection。后一种写法先取连接选项 milvus.database.name，未提供才使用 default；空名称、多余的点在发 RPC 前拒绝。
  • 普通管理过程每次调用只创建一个 MilvusClient，在 driver 上顺序完成该过程所需 RPC，并在成功或失败时关闭。成功的空列表保持空列表；响应缺 status、网络、认证和超时错误以及除下述情况外的非成功 status 都使过程失败。唯一例外是 DescribeIndex 明确返回 IndexNotExist：describeIndexes 将它规范为空索引列表，使无索引 collection 的 describe 仍能输出 schema 字段。
  • 名称、说明、字段名、索引名和索引参数不做连接器侧语义改写；只拒绝空的必填字符串、负数保护期和非正等待超时。
  • describe 的 segment count 是 GetPersistentSegmentInfo 返回的段数，不把各段 num_rows 相加冒充当前可见行数。schema 字段按 Milvus 顺序输出；同一字段有多个索引时输出多行，无索引时索引列为 NULL。

3.2 有界等待

create_index、load 和 compact 默认只提交一次 RPC。显式 wait => true 才轮询，timeout_seconds 默认 600 秒；给出 timeout 却不打开 wait 是参数错误， 避免一个看似生效的参数被忽略。等待规则如下：

过程成功终态失败终态
create_indexFinishedFailed；错误包含 Milvus 的 fail_reason
loadLoadStateLoadedLoadStateNotExist
compactCompleted 且 failed/timeout plan 都为 0未定义状态，或 Completed 时仍有 failed/timeout plan

其它中间状态继续轮询，超过截止时间抛出包含过程名、collection 和最后状态的异常。 每次状态 RPC 都以当时剩余的整体等待时间为 deadline，单次 RPC 不能越过 timeout_seconds 的总截止时间。轮询只在 driver 上发生，不创建 Spark job，不把 client 或凭证序列化给 executor。

六、对能力表和模块表的改动

  • spark.extensions 提供四条线共用的 SQL 前端；spark.procedure 认领 A1–A5 并实现全部过程体。
  • client.api 提供快照、索引、生命周期、描述与登记所需的 RPC 封装，并校验响应状态。
  • 中英文 reference 的 CALL 章节公开列出命令、参数、结果和等待规则，不使用内部工作项缩写。
  • A7 仍列在「尚未落地」：作业清单没有 collection 所有权，保留期与活跃作业判定未定，不能安全提供批量清理。

七、已定与边界

三件 2026-09-16 定案(决策日志同日):连接与存储选项走命名参数;3.5 线的 spark.functions 包删除;register 的结果表用第三节那四列。 实现在同一天落地(#17):spark.sql("CALL milvus.system.register(...)") 在 UAT 上完成 #16 的登记。 #141 随后补齐第三节所列管理过程及其 client RPC、资源关闭和有界等待测试。
