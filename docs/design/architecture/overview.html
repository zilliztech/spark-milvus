把 Milvus 的数据格式接进 Spark，这次分层做

2.0 让一个 collection 在 Spark 里是一张表：读直接读对象存储上的快照，不经 Milvus 服务；写按 Milvus Storage 格式落文件，登记归 Milvus；向量搜索输入一组查询，按段并行、按查询合并。代码分四层，核心层不依赖 Spark，原生层只接 milvus-storage 和 Knowhere 的上游绑定。

1.x 在 v1.6.0 冻结，2.0 在 refactor/v2 上重写。下面七张图是当前的规划，绿色是我们要写的，灰色是不改的，琥珀色是卡在 Milvus 侧的。

01分层与模块

1.x 的七条路径各带一套入口、配置、凭证和类型处理，没有一层封装 Milvus Storage 的读写。2.0 把这一层抽出来：接口层只做翻译，核心层做全部计算，原生层只接两个上游库的 JNI 与 Java API。

我们写的代码 我们写的模块 不改的：Spark、Milvus、对象存储 卡在 Milvus 侧

02目录与包

每个模块一个目录，每个包一个职责。spark-base 不是独立模块，是四条 Spark 线共同引用的源码目录；存储库和 proto 是上游子模块。

03读路径

读全程不经 Milvus 服务：driver 只碰元数据，从快照定分区和谓词；executor 只碰自己那一片，把删除和谓词合成一张位图，交出列批。

拷贝账：多出来的四次都在布局一致的地方

04写路径与登记

写止于作业清单。段按 Milvus Storage 格式直接落对象存储，把它们变成 collection 的一部分是 Milvus 的动作。今天两种登记的现状不同：给已有段加列组有接口，登记新段没有。

05向量搜索与建索引

向量搜索只有一个入口：输入一组查询，按段并行、按查询合并，合并后才回表取输出列。精确扫描和索引探查是同一个段内执行器的两种策略；建索引是写之后单独的一步，经 Milvus 的外部快照恢复交付。

06构建矩阵

跟 lance-spark 一样：一份源码，每条维护中的 Spark 线编译一次，各自钉本线的 Spark、Arrow、antlr 和 Java 版本。共用模块必须按最低的那条线编译。

Arrow 由 Spark 线提供，core 的 Milvus 表达式解析器手写。核心层是四条线共用的单一产物；Spark 3.5 带 antlr 4.9.3，4.x 带 4.13.1，生成码不能成为 core 的公共实现。只有 SQL 扩展文法放在共享源码目录并按线生成，运行时使用本线 Spark 自带的 antlr。R7 的标量 PlanParser 同时用于普通表 milvus.filter 与索引查询过滤；JSON/Array 语义受开放决策 23 阻塞。

08顺序

只有依赖，没有日期。判据是先做让下游列式算子能接上的部分：读路径是一切的基础，写路径的 append 等 Milvus 侧的接口，搜索层依赖列式读。

  1. 拆模块P0sbt 拆 core、native、spark 四条线，依赖规则进构建。不拆，后面每一项都在旧结构上打补丁。
  2. 核心层对象模型P0SnapshotCatalog 与 Snapshot、Segment、Manifest；四份类型映射合并成一份；路径归一。
  3. 列式读P0milvus-storage 上游 JNI、列式 reader、ColumnVector、删除位图。拷贝从 6 次降到 2 次，下游算子拿得到地址。
  4. 读外表P0external collection 和普通 collection 一样是表，走同一条读路径；等 milvus-storage 接受空 schema。
  5. 接口层P1Catalog 目录、三段名与表 DDL，元数据列、统计、V2 谓词、Limit。回表在这一步到位。
  6. 谓词求值P1R6 的 V2 Predicate 翻译、PredicateExpr 与列批位图已接通；R7 的 Expr / PlanParser / Evaluator 已同时接入普通表 milvus.filter 与索引搜索前过滤，只有 JSON/Array 与 json_contains 语义等待决策 23。
  7. 写路径P1SegmentWriter、Committer、register。backfill 分支可先做，append 等 Milvus 的 RPC，两件事可以并行谈。
  8. 向量层P2上游 Knowhere Java/JNI、查询集入口（V5、V7）、建索引（W6，BuildIndexProcedure）与快照交付（W8，WriteSnapshotProcedure / RestoreSnapshotProcedure）已实现；待做的是 backfill 写模式。
  9. 产物与基准P3native jar 打包、四条 Spark 线的 CI 矩阵、读吞吐与拷贝次数与写端到端的基准；macOS 与 GPU 产物。
  10. 2.0.0 发布P3云上作业切换坐标与 SHA。
