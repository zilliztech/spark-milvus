# Milvus Spark Connector {{VERSION}}

The 3.0 line targets Milvus 3.0. It reads fixed Storage V3 snapshots directly
from object storage and replaces stored columns from a Spark DataFrame.

## Capabilities

- Read snapshot data with DataFrames and Spark SQL, including projection, scalar
  filters, delete handling and Arrow columnar batches. The read operates on the
  snapshot's fixed data state without querying a running Milvus service.
- Read physical rows with their stored row identities, compute new values in
  Spark, and replace eligible stored columns. The connector writes new column
  files, commits segment manifest revisions and produces a receipt.
- Use Spark 3.5 with Scala 2.12 or 2.13, or Spark 4.0, 4.1 and 4.2 with Scala
  2.13. Bundled Maven distributions cover Spark 4.0 and 4.2; thin modules cover
  all five combinations.

The caller supplies and protects the snapshot, computes replacement values, and
registers the resulting revisions with Milvus. A successful connector write does
not make the new values visible online by itself. Segment commits are separate;
there is no collection-wide atomic switch.

## Getting started

For a Spark 4.0 / Scala 2.13 application, resolve
`com.zilliz:spark-milvus-4.0_2.13:{{VERSION}}` from Maven Central. This universal
entry brings the JVM implementation and the released native platforms. Use
`spark-milvus-4.0-linux-x86_64_2.13` for a Linux x86_64 deployment, or replace
`4.0` with `4.2` for that Spark line.

See the
[installation guide](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/README.md#installing)
for Maven, sbt, `--packages` and the required Java signal-library setup.

## Migration

- **From 1.x:** the 1.x line ended at `v1.6.0`. Configure an existing Snapshot
  path and object-storage access for 3.0; legacy storage formats and the earlier
  service-based connector API are outside this release.
- **From 2.0:** vector search, persisted-index search and Nearest Join
  are no longer provided. Vectors remain readable and replaceable as data
  columns, subject to the write restrictions. Remove the old connector session
  extension and `MilvusSparkPlugin` settings; reads require neither.
- **Dependencies:** the four production modules are `native-runtime`,
  `native-storage`, `core` and `spark`. Public native bundles contain Storage
  only. Upgrade the JVM and native artifacts together; do not mix earlier
  bundles or overlapping thin, bundled-JVM and assembly classes.
- **Snapshot and write contracts:** snapshot metadata must declare
  `format_version` 4 or 6. Nonempty inputs use `milvus.snapshot.path`. Column
  replacement requires every stored row exactly once, including deleted rows,
  and preserves its row identity. Indexed fields, keys and other protected
  fields cannot be replaced. `mode("append")` selects the batch write protocol;
  it does not insert new rows.

Read the [reference](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/reference.md)
and [column replacement guide](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/column-replacement.md)
before migrating an existing application.
