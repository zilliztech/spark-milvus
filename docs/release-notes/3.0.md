# Milvus Spark Connector {{VERSION}}

> **Release-note template.** Replace `{{VERSION}}` with the published version
> and remove this notice when preparing the GitHub announcement.

**Upgrading from 3.0.0?** Replace `milvus.segments` before upgrading. The
reader silently ignores this option, so a job that keeps it can return rows
from additional segments. To keep the same rows, use a Spark predicate such
as `.where("_segment_id IN (100, 101)")`.

Spark-Milvus {{VERSION}} reads fixed Milvus 3.0 Storage V3 snapshots and
replaces stored columns from a Spark DataFrame. This release exposes snapshot
metadata by name, reports read and write progress in Spark, and records which
segment commits storage acknowledged during column replacement.

## Migrating snapshot reads from 3.0.0

Spark evaluates predicates on the hidden `_segment_id` column after the scan.
To skip entire partitions before reading their segments, use a top-level
equality or `IN` condition on the hidden `_partition_id` column.

| Former reader option | How to migrate |
| --- | --- |
| `milvus.segments` | Use `.where("_segment_id IN (100, 101)")` to select rows from those segments. |
| `milvus.partitions` | Use `.where("_partition_id IN (10, 11)")` to prune partitions. An ID absent from the snapshot matches zero rows. |
| `milvus.filter` | Use a DataFrame or SQL predicate such as `.where("category = 1 AND rating >= 2.0")`. Spark SQL comparison and NULL semantics apply. For exact equality with a stored float such as `1.1f`, use `rating = CAST(1.1 AS FLOAT)`. |
| `fieldIDs` | Select collection fields by name, for example `.select("id", "score")`. To read the stored system field with ID 0 when the collection schema omits it, include `RowID BIGINT` in the explicit read schema. |
| `milvus.extra.columns` | Select hidden columns by name, for example `.select("*", "_segment_id", "_row_offset", "_timestamp")`. A bare `*` returns the visible collection fields. |
| `milvus.read.apply.deletes` | The default read returns live rows. To include rows marked deleted, set `milvus.read.mode=physical`. |
| `milvus.read.include_row_id` | On a physical read, select `_milvus_row_id` explicitly and carry it unchanged through to the replacement write. The snapshot must have a positive `snapshot_info.id`. |
| `milvus.read.columnar` | Remove the option. Live and physical scans deliver Arrow batches. Spark converts batches to rows when a downstream operator needs them. Remove the retired `milvus.rows.materialized` counter from dashboards. |

A snapshot read fails during planning if any of the other seven former
options is present. For SQL over a temporary view, select the hidden columns
into the view before registering it.
[Snapshot read reference](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/reference.md#23-data-operation-parameters)

## Column replacement and recovery

Supply a fixed Storage V3 snapshot with metadata `format_version` 4 or 6.
Read it in physical mode and carry every stored row through the write exactly
once, including rows marked deleted. Use `mode("append")` and
`milvus.write.operation=replace_columns` with a fresh result address. Key
fields, indexed fields and other Milvus-managed fields are protected from
replacement.

Each write claims its result address by conditionally creating
`_operation.json` and a guard at the 3.0.0 claim key. Writers using either
version recognize an occupied address. Each result record uses a single upload
request on object storage. Creating the receipt is also conditional, so a
second writer cannot overwrite it. Column replacement requires a backend with
create-if-absent support. On Huawei OBS the connector supports snapshot reads
only.

Segments commit independently. The driver publishes `_result.json` after
storage acknowledges every segment's manifest commit. If an acknowledgement is
lost and the outcome is uncertain, `_failure.json` records the segment as
`unknown` and includes its `candidate_version` for inspection. The writer
retains files from submitted commits because a manifest may reference them.
The caller registers the resulting revisions with Milvus for online visibility.
[Column replacement and recovery](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/column-replacement.md#the-write-result-address)

## Monitoring and storage

- Track planned and completed segments, decoded and emitted rows, and rows removed by deletes or predicates in Spark SQL. The optional `com.zilliz.spark.connector.metrics.MilvusMetricsPlugin` aggregates metrics on the driver for Spark sinks such as Prometheus. Spark 3.5 requires the plugin for driver write milestones, including committed segments and receipt publication. Spark 4.x also shows those milestones in the SQL UI. [Metric definitions](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/monitoring.md)
- With `fs.use_iam=true`, the native AWS chain checks environment credentials, then web identity such as IRSA. To use an EC2 instance profile, set `AWS_EC2_METADATA_ENABLE=true` on the driver and every executor. Applications relying on ECS task roles, EKS Pod Identity, shared credential profiles, credential processes or SSO must switch credential sources. [Storage settings](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/reference.md#22-storage-location-and-credentials)
- S3-compatible uploads use CRT by default on supported backends. Set `fs.s3.use_crt=false` to disable it. This setting applies to data uploads. The native storage update also fixes a JVM shutdown hang after S3 access. [Storage settings](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/reference.md#22-storage-location-and-credentials) · [Shutdown fix](https://github.com/zilliztech/spark-milvus/pull/220)
- Snapshot index metadata now preserves the optional scalar index serialization version. Scala callers constructing `IndexFileEntry` or `SegmentIndex` directly must supply the new `currentScalarIndexVersion: Option[Int]` argument. [Index model change](https://github.com/zilliztech/spark-milvus/pull/216)

## Maven artifacts and runtime requirements

The release contains 28 Maven coordinates in group `com.zilliz`. Spark 3.5
supports Scala 2.12 and 2.13 with Java 17. Spark 4.0, 4.1 and 4.2 support
Scala 2.13 with Java 21. All five combinations were available in 3.0.0,
including the Spark 3.5 and 4.1 packages added on November 16, 2026.
Applications using a 3.0.0 Thin artifact must switch to a bundled entry.
[Artifact selection and build provenance](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/release-artifacts.md)

For Spark 4.0 and Scala 2.13, the universal coordinate is
`com.zilliz:spark-milvus-4.0_2.13:{{VERSION}}`. Set both your build dependency
and `RELEASE_VERSION` in the launch examples to `{{VERSION}}`.

```xml
<dependency>
  <groupId>com.zilliz</groupId>
  <artifactId>spark-milvus-4.0_2.13</artifactId>
  <version>{{VERSION}}</version>
</dependency>
```

| Artifact ID | What it provides | Count |
| --- | --- | ---: |
| `spark-milvus-<line>_<scala-binary>` | Universal entry that resolves the JVM implementation and all three native platforms | 5 |
| `spark-milvus-<line>-<platform>_<scala-binary>` | Platform entry that resolves the JVM implementation and one native platform | 15 |
| `spark-milvus-<line>-jvm_<scala-binary>` | Bundled JVM implementation for a Spark/Scala combination | 5 |
| `spark-milvus-native-<platform>` | Native Storage libraries shared across the five combinations | 3 |

The platform IDs are `linux-x86_64`, `linux-aarch64` and `darwin-aarch64`.
Linux requires glibc 2.35+ and a C++ runtime providing `GLIBCXX_3.4.30` and
`CXXABI_1.3.13`. Apple silicon requires macOS 14+. For a local-JAR
deployment, use the JVM JAR and one matching native JAR, both at version
{{VERSION}}. The cluster supplies Spark. Configure signal-library loading on
the driver and every executor.

## Migrating from earlier connector lines

- **From 1.x** (last release `v1.6.0`), supply an existing Storage V3 snapshot path and object-storage credentials. The caller prepares and protects the snapshot and its referenced files.
- **From 2.0**, remove the old connector session extension and `MilvusSparkPlugin` settings. Move vector search, persisted-index search and Nearest Join out of the connector. Spark applications can still read and replace eligible vector fields as data columns.
