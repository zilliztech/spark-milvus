The 3.0 line targets Milvus 3.0. It reads fixed Storage V3 snapshots directly
from object storage and replaces stored columns from a Spark DataFrame.

## Capabilities

- Read snapshot data with DataFrames and Spark SQL, including projection, scalar
  filters, delete handling and Arrow columnar batches. The read operates on the
  snapshot's fixed data state without querying a running Milvus service.
- Read live rows by default. Set `milvus.read.mode=physical` to include rows
  marked deleted. Project fields by name and use `WHERE _partition_id IN (...)`
  to prune partitions. Select `_segment_id`, `_row_offset` and `_timestamp` to
  inspect a row's position and stored timestamp.
- Select the hidden `_milvus_row_id` on a physical read, compute new values in
  Spark, and replace eligible stored columns. The connector writes new column
  files, commits segment manifest revisions and produces a receipt.
- Use Spark 3.5 with Scala 2.12 or 2.13, or Spark 4.0, 4.1 and 4.2 with Scala
  2.13. Universal and platform-specific Maven entries cover all five
  combinations with one consistent packaging model.

The caller supplies and protects the snapshot, computes replacement values, and
registers the resulting revisions with Milvus. A successful connector write does
not make the new values visible online by itself. Segment commits are separate;
there is no collection-wide atomic switch.

## Getting started

All artifacts are published to Maven Central under group `com.zilliz`, with
version `{{VERSION}}`. Use the same connector version for every JVM and native
artifact, and match the Spark line and Scala binary version to your application
and cluster.

For Spark 4.0 / Scala 2.13, add this Maven dependency:

```xml
<dependency>
  <groupId>com.zilliz</groupId>
  <artifactId>spark-milvus-4.0_2.13</artifactId>
  <version>{{VERSION}}</version>
</dependency>
```

Its full coordinate is `com.zilliz:spark-milvus-4.0_2.13:{{VERSION}}`.
This universal entry resolves the JVM implementation and all released native
platforms; the loader selects the current platform. For a Linux x86_64
deployment, use `spark-milvus-4.0-linux-x86_64_2.13` to resolve only that native
platform. Replace `4.0` with `3.5`, `4.1` or `4.2` for that Spark line. Spark
3.5 also supports Scala 2.12: use the `_2.12` suffix for that distribution.
Spark itself is provided by the application or cluster.

### Choose an artifact

For bundled artifacts, `<line>` is `3.5`, `4.0`, `4.1` or `4.2`. The Scala
suffix is `_2.12` or `_2.13` for Spark 3.5 and `_2.13` for Spark 4.x. The
available `<platform>` values are `linux-x86_64`, `linux-aarch64` and
`darwin-aarch64`.

| Artifact ID | Contents and use |
|---|---|
| `spark-milvus-<line>_<scala-binary>` | Universal dependency entry: the JVM implementation and all released native platforms. |
| `spark-milvus-<line>-<platform>_<scala-binary>` | Platform dependency entry: the JVM implementation and one native platform. |
| `spark-milvus-<line>-jvm_<scala-binary>` | Bundled JVM implementation without Milvus native libraries; supply one matching native platform separately. |
| `spark-milvus-native-<platform>` | Storage native libraries and their dependencies for one platform. |

## Migration

- **From 1.x:** the 1.x line ended at `v1.6.0`. Configure an existing Snapshot
  path and object-storage access for 3.0; legacy storage formats and the earlier
  service-based connector API are outside this release.
- **From 2.0:** vector search, persisted-index search and Nearest Join
  are no longer provided. Vectors remain readable and replaceable as data
  columns, subject to the write restrictions. Remove the old connector session
  extension and `MilvusSparkPlugin` settings; reads require neither.
- **From 3.0.0:** the `milvus.filter` read option has been removed. Spark SQL
  and DataFrame filters are the only filter input, and the connector pushes
  supported predicates down to the scan. A read that still sets the option
  fails during planning instead of returning unfiltered rows. Rewrite each
  expression as a Spark condition: for example,
  `.option("milvus.filter", "category == 1 and rating >= 2.0")` becomes
  `.where("category = 1 AND rating >= 2.0")`. The condition then follows
  Spark SQL semantics. Spark compares a Float field as a double, so
  `rating = 1.1` does not match a stored `1.1f` the way `rating == 1.1` did;
  write `rating = CAST(1.1 AS FLOAT)` instead.
- **From 3.0.0, AWS credentials:** with `fs.use_iam=true`, set explicitly or as
  the fallback, the bundled native library reads environment variables, then a
  web identity token such as IRSA, and the EC2 instance profile only when
  `AWS_EC2_METADATA_ENABLE=true` is set for the driver and every executor. ECS
  task roles, EKS Pod Identity, profile keys, credential processes and SSO are
  no longer used; the reference describes the chain under storage credentials.
- **From 3.0.0, column replacement:** a write claims its result address by
  conditionally creating `_operation.json` and also creates a guard at the
  3.0.0 claim key, so 3.0.0 rejects addresses this release claimed and this
  release rejects addresses 3.0.0 claimed. Huawei OBS does not support the
  conditional creation the claim needs, so column replacement is unavailable
  there. S3-compatible uploads other than column replacement records use the
  CRT transport by default, which `fs.s3.use_crt=false` turns off.
- **Dependencies:** the four production modules are `native-runtime`,
  `native-storage`, `core` and `spark`. Public native bundles contain Storage
  only. Upgrade the JVM and native artifacts together; do not mix earlier
  bundles or overlapping bundled-JVM and assembly classes. New releases no
  longer publish Thin modules. Applications using them should switch to the
  matching universal or platform-specific entry. Existing Thin artifacts remain
  available with their original bytes.
- **Snapshot and write contracts:** snapshot metadata must declare
  `format_version` 4 or 6. Nonempty inputs use `milvus.snapshot.path`. Column
  replacement requires every stored row exactly once, including deleted rows,
  and preserves its row identity. Indexed fields, keys and other protected
  fields cannot be replaced. `mode("append")` selects the batch write protocol;
  it does not insert new rows.

and [column replacement guide](https://github.com/zilliztech/spark-milvus/blob/v{{VERSION}}/docs/column-replacement.md)
